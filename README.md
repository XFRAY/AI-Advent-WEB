# День 18 · Фоновые денежные сводки Altegio

Агент управляет собственным MCP-планировщиком: собирает движение денег за сегодня
по филиалу, сохраняет расписание и результаты в JSON, показывает историю в приложении.
Каталог услуг дня 17 также доступен. Ветка предыдущего дня: `day_17`.

## Запуск

Нужен Node.js 20.19+.

```sh
npm install
cp .env.example .env # только если .env ещё нет
npm run dev
```

Frontend: http://localhost:5173. Backend: http://127.0.0.1:3001.
Собранное приложение: `npm run build`, затем `npm start`.

Настройки `.env`: `OPENAI_API_KEY`, `OPENAI_MODEL`, `ALTEGIO_PARTNER_TOKEN`, `PORT`.
Для автоматического восстановления подключения после перезапуска задайте также
`ALTEGIO_USER_TOKEN` и `ALTEGIO_LOCATION_ID`. Backend проверяет филиал по доступному
пользователю списку. Единственный доступный филиал выбирается автоматически.
Если список не загрузился, сбор ожидает выбора филиала.

Вход через форму хранится только в памяти; после перезапуска потребуется войти снова.
Пароль не сохраняется, токен не возвращается браузеру или модели. Выход приостанавливает
задачу и удаляет токен из текущего процесса, но не редактирует `.env`.
Это локальное приложение с одним подключением и общим диалогом, без многопользовательских сессий.

## Как пользоваться

1. Войдите в Altegio и выберите филиал с доступом к финансовым операциям.
2. В панели «Деньги за сегодня» укажите интервал (1–1440 минут, по умолчанию 60).
3. Часовой пояс определяется автоматически из `timezone_name` филиала; отдельного поля
   в панели нет. Если Altegio его не возвращает, timezone можно указать через чат.
4. Нажмите «Включить / обновить»: первый сбор выполняется сразу. Следующий — через
   заданный интервал после завершения предыдущего.
5. «Пауза» останавливает расписание; «Собрать сейчас» сохраняет новый снимок.
   История и последняя успешная сводка отображаются отдельно от чата.

Можно управлять через чат:

- «Собирай денежную сводку каждый час».
- «Собирай сводку каждую минуту, часовой пояс Europe/Warsaw».
- «Приостанови сбор».
- «Собери сводку сейчас».
- «Покажи последние пять сводок».

Панель обновляется каждые 5 секунд на открытой видимой странице. Расчёты и автоматический
текст выполняются кодом без обращения к модели. Ключ OpenAI нужен для чата, но не для
кнопок панели или фонового сбора.

## Что считается

Источник: `GET /api/v1/transactions/{location_id}`, с фильтрами
`start_date/end_date=YYYYMMDD`, `real_money=1`, `deleted=0`, `balance_is=0`.
Запрашиваются все страницы (`page/count`), максимум 100 страниц по 200 операций.
Метаданные филиала: `GET /api/v1/company/{location_id}`.

- Положительные суммы — поступления; отрицательные — списания (в сводке положительная величина).
- Итог = поступления минус списания. Это **движение денег**, не выручка и не прибыль.
  Авансы, переводы и другие реальные движения входят в результат, если API включает их в выборку.
  Списания не объявляются возвратами.
- Каждая сводка заново рассчитывает сегодняшний день по времени филиала. Старые снимки
  не суммируются; изменения и удаления транзакций отражаются при следующем сборе.
- Десятичные JSON-токены сохраняются до преобразования в `Number`; расчёты выполняются
  через `BigInt` с десятичным масштабом. Денежные итоги в JSON возвращаются строками.
- Валюта используется только при наличии явного значения в метаданных филиала.
  Если её нет, возвращается `currency: null` и надпись «валюта не указана».
- Неверная дата/сумма, повтор страницы, HTTP-ошибка, таймаут или предел страниц означают
  ошибку всего запуска, а не частичный или нулевой итог. Успешная пустая выборка даёт нули.

Altegio меняет данные во время чтения; API пагинации не обеспечивает транзакционный снимок.
Сводка показывает результат последней полной загрузки, без обещания бухгалтерской сверки.
Исходные транзакции, имена и телефоны клиентов на диск и в модель не передаются.

## Планировщик и хранение

Backend запускает MCP-процесс через stdio при старте, до первого запроса пользователя.
Планировщик живёт внутри MCP. Backend восстанавливает процесс при его неожиданном завершении.
Открытый браузер для работы не нужен; необходимы работающий backend, интернет и бодрствующий компьютер.
Развёртывание на отдельном сервере в эту версию не входит.

Одна задача привязана к филиалу. Повтор одинаковой настройки не создаёт задачу или лишний сбор.
Смена филиала и выход приостанавливают задачу; включение на новом филиале перепривязывает её.
История остаётся с указанием исходного филиала. Одновременные сборы исключены;
повторный ручной запуск во время фонового сбора возвращает состояние текущего выполнения.
При изменении подключения backend дожидается текущего сбора перед остановкой MCP.

`data/summary.json` хранит версию формата, расписание, успешные агрегаты и ошибки запусков.
Путь можно изменить через `SUMMARY_STORE_PATH`. Каталог `data/` исключён из Git.
Записи последовательные, через временный файл и атомарное переименование; файлы создаются
с правами `0600`. Блокировка запрещает двум MCP-процессам одновременно владеть хранилищем.
Повреждённый JSON не перезаписывается. История хранится целиком; API выдаёт последние 1–100 запусков.

После перезапуска расписание восстанавливается. Пропущенные интервалы объединяются в один
актуальный сбор. Незавершённый запуск отмечается как прерванный. Ошибки сети повторяются
в следующий интервал; ошибка авторизации/доступа переводит задачу в ожидание подключения.
Предыдущая успешная сводка сохраняется. Токены и пароли в JSON не записываются.
История обычного чата по-прежнему хранится в памяти.

## MCP и HTTP API

| MCP-инструмент | Аргументы | HTTP |
|---|---|---|
| `summary_schedule_set` | `intervalMinutes` (по умолчанию 60), необязательный `timezone` | `POST /api/summary/schedule` |
| `summary_schedule_status` | `{}` | `GET /api/summary/status` |
| `summary_schedule_pause` | `{}` | `POST /api/summary/pause` |
| `summary_run_now` | необязательный `timezone` | `POST /api/summary/run` |
| `summary_results` | `limit` (1–100, по умолчанию 20) | `GET /api/summary/results?limit=20` |

Состояние: `scheduled`, `running`, `paused`, `waiting_connection`. Результат сбора:
`locationId`, `locationTitle`, `timezone`, `date`, `collectedAt`, `currency`,
`incoming`, `outgoing`, `net`, `transactionCount`, `text`.
Ошибки выполненного сбора возвращаются как `run.status: error` с безопасным описанием.
Внутренний `_summary_shutdown` нужен только для завершения процесса и не доступен агенту.

Сохранены `altegio_list_services` (`query`, `limit`), маршруты `/api/altegio/*`,
`GET /api/health`, `GET/DELETE /api/messages`, `POST /api/chat`.
Для MCP-команд агент и клиент используют общий реестр схем и разрешённых инструментов.
Каталог услуг использует Altegio V2, поиск по названию с кандидатами при отсутствии
буквального совпадения; отсутствующие цены и валюта возвращаются как `null`.

## Проверка

```sh
npm test
npm run build
npm run mcp:list
```

Тесты не требуют ключей: реальные MCP-процессы и HTTP приложения работают с подменёнными
ответами Altegio и модели, временными хранилищами и управляемыми часами. Проверяются
арифметика, страницы, границы дня, ошибки, авторизация, пауза, параллельные вызовы,
смена филиала, восстановление, блокировка файла и команды через чат.
CLI discovery использует временное хранилище и не запускает сохранённую рабочую задачу.

Демонстрация с подключённым Altegio:

1. Включить интервал 1 минута; проверить первый результат и время следующего сбора.
2. Закрыть страницу на 2 минуты, оставив backend включённым.
3. Открыть приложение: в истории должны появиться дополнительные снимки.
4. Перезапустить backend. При токене в `.env` задача продолжится автоматически;
   при входе через форму сначала войти и выбрать тот же филиал.
5. Сверить суммы с финансовыми операциями Altegio за тот же день и филиал.
6. Нажать «Пауза», убедиться, что следующий запуск отсутствует.

Документация: [транзакции Altegio](https://developer.alteg.io/en/b2b-v1/openapi/payments/get_transactions),
[услуги V2](https://developer.alteg.io/en/b2b-v2/openapi/services/list_services),
[ключи Altegio](https://developer.alteg.io/en/get-api-key).

Кнопка «Очистить всё» вызывает `DELETE /api/history`: удаляет переписку, все сохранённые
запуски, последнюю сводку и расписание — всё хранилище `data/summary.json` сбрасывается.
Текущий сбор завершается перед очисткой. Сохраняется только вход в Altegio (токены и
выбранный филиал), поэтому после очистки можно сразу включить сбор заново.
