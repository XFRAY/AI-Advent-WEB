# День 21 · Индексация документов

Локальный пайплайн превращает встроенный корпус Markdown, исходного кода и PDF в два JSON-индекса с embeddings и метаданными. Веб-панель строит индексы, показывает статистику и сравнивает семантическую выдачу двух стратегий chunking. Ветка предыдущего дня — `day_20`.

## Что индексируется

Состав корпуса описан в `corpus/manifest.json`:

- README и две учебные статьи;
- JavaScript/JSX-код проекта;
- шестистраничное PDF-руководство.

На текущей версии корпуса это 48 документов и около 37 000 токенов — примерно 75 условных страниц по 500 токенов. `npm run corpus:pdf` воспроизводимо пересобирает PDF-артефакт.

Каждый формат преобразуется в общий документ `{ source, title, file, type, text, sections }`. Markdown делится по заголовкам, PDF сохраняет страницы, код — объявления функций, классов и переменных верхнего уровня.

## Стратегии chunking

| Стратегия | Правило | Компромисс |
|---|---|---|
| `fixed` | окно 500 токенов, overlap 75 | предсказуемый базовый вариант, но может пересекать границы разделов |
| `structured` | секции документа, крупные секции — окна до 700 токенов с overlap 75 | сохраняет заголовки, страницы и блоки кода, но размеры чанков неравномерны |

Токенизатор локальный и детерминированный: считает слова, числа и знаки пунктуации. Это приблизительная, но воспроизводимая оценка токенов модели.

Каждый чанк содержит текст и метаданные:

```json
{
  "source": "ai-advent-articles",
  "title": "chunking-strategies",
  "file": "corpus/articles/chunking-strategies.md",
  "section": "Структурное разбиение",
  "chunk_id": "d91a…",
  "strategy": "structured",
  "position": 3,
  "token_start": 0,
  "token_end": 185,
  "token_count": 185
}
```

`chunk_id` — стабильный SHA-256-хеш стратегии, файла, секции, позиции и текста.

## Индексы и поиск

Embeddings создаются моделью `text-embedding-3-small` пакетами по 64 чанка. Готовый индекс сначала полностью формируется, записывается во временный файл и только затем атомарно заменяет предыдущий JSON. Ошибка API не оставляет обрезанный файл.

Индексы находятся в игнорируемом Git каталоге `data/indexes`:

```text
data/indexes/fixed.json
data/indexes/structured.json
```

Файл содержит версию схемы, дату, embedding-модель и размерность, параметры chunking, статистику, чанки, метаданные и векторы. При чтении схема и размерность проверяются. Поиск создаёт один embedding запроса и вычисляет cosine similarity локально для обоих индексов.

## Запуск

Нужен Node.js 20.19+ и OpenAI API key.

```sh
npm install
cp .env.example .env
npm run dev
```

Откройте http://localhost:5173, нажмите «Построить оба индекса», затем выполните запрос. Без `OPENAI_API_KEY` корпус и состояние видны, но построение и поиск вернут понятную ошибку.

CLI использует тот же pipeline:

```sh
npm run index
npm run index -- --strategy fixed
npm run index -- --strategy structured
```

После выполнения печатается таблица с количеством документов и чанков, средним/минимальным/максимальным размером, временем и размером JSON-файла.

## HTTP API

- `GET /api/indexes` — корпус, состояние двух индексов и сравнительная статистика.
- `POST /api/indexes/build` — `{ "strategy": "all" | "fixed" | "structured" }`; параллельный запуск отклоняется с `409`.
- `GET /api/indexes/:strategy/chunks?offset=0&limit=20` — тексты и метаданные без тяжёлых векторов.
- `POST /api/search` — `{ "query": "…", "strategy": "all", "topK": 5 }`.
- `GET /api/health` — состояние сервера и флаг индексации.

## Проверка

```sh
npm test
npm run build
npm run corpus:pdf
```

Тесты работают без OpenAI key: используется детерминированный embedder. Они проверяют парсеры Markdown/кода/PDF, объём корпуса, overlap и структурные границы, стабильные идентификаторы, пакетную индексацию, схему JSON, атомарное сохранение, cosine ranking, CLI и HTTP API, включая валидацию и защиту от конкурентного запуска.
