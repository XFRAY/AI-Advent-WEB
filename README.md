# День 22 · Первый RAG-запрос

Приложение принимает один вопрос и параллельно получает два ответа одной модели: обычный и дополненный тремя релевантными фрагментами локальной базы знаний. Интерфейс показывает ответы рядом, время выполнения и источники RAG-ответа.

## Как работает RAG

```text
вопрос → embedding → cosine search → top 3 чанка → вопрос + контекст → LLM
```

Режим без RAG отправляет модели только вопрос. Режим с RAG использует структурный индекс: Markdown делится по заголовкам, PDF — по страницам, а большие секции — окнами до 700 токенов с overlap 75. Каждый найденный фрагмент передаётся модели с меткой `[S1]`, `[S2]` или `[S3]`. Модель должна отвечать только по контексту и ссылаться на эти метки.

Оба вызова независимы: ошибка одного режима не скрывает успешный ответ второго.

## База знаний

Стабильный корпус описан в `corpus/manifest.json` и содержит:

- этот README;
- две статьи об индексации и chunking;
- шестистраничное PDF-руководство.

Исходный код приложения не входит в корпус, поэтому переиндексация после изменения реализации не меняет предметную базу. Полный индекс сначала записывается во временный файл и только после успеха атомарно заменяет `data/indexes/structured.json`.

## Контрольный набор

`corpus/evaluation.json` содержит 10 вопросов. Для каждого зафиксированы ожидаемое содержание ответа и целевые источники. Кнопка «Запустить все» последовательно выполняет 20 генераций — по два режима на вопрос — чтобы не создавать всплеск параллельных API-запросов.

После прогона пользователь вручную отмечает соответствие каждого ответа ожиданию. Итоговые счётчики позволяют сравнить качество режима без RAG и с RAG без отдельной модели-судьи.

## Запуск

Нужен Node.js 20.19+ и OpenAI API key.

```sh
npm install
cp .env.example .env
npm run dev
```

Откройте http://localhost:5173 и сначала нажмите «Построить индекс». По умолчанию используются `gpt-5.6-terra` для ответов и `text-embedding-3-small` для embeddings; обе модели настраиваются через `.env`.

Structured-индекс также можно построить из CLI:

```sh
npm run index
```

## HTTP API

- `GET /api/index` — состояние корпуса и structured-индекса.
- `POST /api/index/build` — построить или атомарно перестроить индекс.
- `POST /api/compare` — `{ "question": "..." }`, два независимых результата сравнения.
- `GET /api/evaluation/questions` — 10 вопросов, ожидания и целевые источники.
- `GET /api/documents/file?path=...` — открыть только файл, входящий в корпус.
- `GET /api/health` — состояние сервера.

## Проверка

```sh
npm test
npm run build
npm run corpus:pdf
```

Тесты не обращаются к OpenAI: детерминированные embedder и generator проверяют полный путь от документов до двух ответов, top-3 retrieval, метки источников, границы недоверенного контекста, частичный успех и HTTP API.
