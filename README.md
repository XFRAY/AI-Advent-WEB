# День 25 · Мини-чат с RAG и памятью задачи

Production-like веб-чат хранит несколько диалогов в SQLite, ищет контекст в локальной базе знаний на каждом ходе и отвечает только подтверждёнными фактами. Каждый grounded-ответ содержит источники и дословные цитаты. Если релевантных чанков нет, чат явно сообщает «источники не найдены» и не генерирует неподтверждённый ответ.

## Память задачи

После каждого сообщения модель возвращает полный структурированный state:

- цель диалога;
- уточнения пользователя;
- ограничения;
- пользовательские термины и их значения.

При retrieval и генерации используются state и последние 20 сообщений. Полная история остаётся в SQLite. Пара «вопрос + ответ» и новый state записываются одной транзакцией только после успешного завершения всего пайплайна.

```text
сообщение + история + task state
        → обновление task state по JSON Schema
        → history-aware query rewrite
        → embeddings → top-K → similarity threshold
        ├─ нет контекста → честный отказ + «источники не найдены»
        └─ есть контекст → grounded JSON → проверка ссылок и цитат
        → атомарное сохранение хода в SQLite
```

## Запуск

Нужен Node.js 20.19+ и OpenAI API key.

```sh
npm install
cp .env.example .env
npm run dev
```

Откройте http://localhost:5173 и постройте индекс. По умолчанию база чатов создаётся в `data/chat.sqlite`; путь можно изменить через `CHAT_DB_PATH`.

## HTTP API

- `GET /api/conversations` — список сохранённых диалогов.
- `POST /api/conversations` — создать диалог.
- `GET /api/conversations/:id` — получить историю и task state.
- `POST /api/conversations/:id/messages` — отправить сообщение.
- `GET /api/index` и `POST /api/index/build` — состояние и построение RAG-индекса.
- `GET /api/documents/file?path=...` — открыть документ из корпуса.

Пример нового сообщения:

```json
{
  "content": "А какой вариант подходит под мой бюджет?",
  "settings": {
    "candidateTopK": 8,
    "resultTopK": 3,
    "similarityThreshold": 0.35
  }
}
```

## Проверка

```sh
npm test
npm run build
```

Тесты используют временные SQLite-базы и детерминированные doubles без обращения к OpenAI. В набор входят два диалога по 10–12 пользовательских сообщений, которые проверяют сохранение цели, ограничений, уточнений, терминов и источников до конца сценария.
