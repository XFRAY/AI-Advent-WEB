# День 9: Управление контекстом и сжатие истории

Web-приложение сравнивает два режима агента на одном и том же пользовательском запросе:

- `Без сжатия` — модель получает всю сохраненную историю как есть.
- `Со сжатием` — модель получает summary старой истории и последние N сообщений без изменений.

Один общий ввод отправляет сообщение сразу в оба режима. Ответы видны рядом, а интерфейс показывает расход токенов до/после и экономию compressed-подхода.

## Запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте `.env` по примеру `.env.example`:

```bash
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-4o-mini
PORT=3001
```

3. Запустите frontend и backend:

```bash
npm run dev
```

4. Откройте локальный адрес Vite, обычно `http://localhost:5173`.

## Как работает compression

Backend хранит две истории в SQLite:

- `full` — полная история для агента без сжатия;
- `compressed` — история для агента со сжатием.

Summary хранится отдельно от сообщений. Для compressed-запроса backend строит input так:

1. системный prompt агента;
2. summary старой истории;
3. последние N сообщений как есть;
4. новый user prompt.

В UI можно менять:

- `Последние N` — сколько последних сообщений оставить дословно;
- `Batch` — через сколько старых сообщений обновлять summary.

Если старые сообщения еще не набрали полный batch, они временно добавляются в summary-блок как pending context, но не отправляются в модель как raw chat history. Так в raw-истории compressed-режима остаются ровно последние N сообщений.

## API

- `GET /api/messages` — возвращает `fullMessages`, `compressedMessages`, `summary`, `compressionStats`.
- `POST /api/context-preview` — считает токены следующего запроса для full и compressed режимов.
- `POST /api/chat/compare` — отправляет один prompt в оба режима и возвращает:
  - `full`;
  - `compressed`;
  - `comparison`.
- `DELETE /api/messages` — очищает обе истории и summary.

## Проверка

```bash
npm test
npm run build
```

Ручной сценарий:

1. Отправьте 12-20 сообщений с деталями, которые агент должен помнить.
2. Сравните ответы в двух колонках.
3. Посмотрите `full`, `compressed` и `saved` в нижней панели.
4. Измените `Последние N` и `Batch`, затем отправьте еще несколько сообщений.

Ожидаемый результат: full input растет быстрее, compressed input использует summary + последние N сообщений и экономит токены.
