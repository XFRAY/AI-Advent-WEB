# День 12: Персонализация ассистента

Web-приложение добавляет явный профиль пользователя поверх трех разделенных слоев памяти. Активный профиль автоматически задает стиль, формат и ограничения каждого ответа без повторного напоминания в чате.

В SQLite при первом запуске создаются два демо-профиля:

- `Краткий деловой` — короткие прямые ответы для рабочих задач.
- `Подробный учебный` — пошаговые объяснения с причинно-следственными связями и примерами.

Оба профиля показаны параллельно и доступны для редактирования. Один общий вопрос отправляется через каждый профиль, поэтому различие в ответах видно сразу. Активный профиль также хранится на сервере для обычного режима `/api/chat`.

Модель памяти продолжает работать отдельно:

- `Short-term memory` — текущий диалог. В модель уходит только последние N сообщений.
- `Working memory` — данные текущей задачи: цель, данные, ограничения, вопросы и следующие шаги.
- `Long-term memory` — устойчивые сведения: профиль, предпочтения, решения и reusable knowledge.

После каждого ответа агент отдельно выбирает, что сохранить в working memory и что сохранить в long-term memory. Профиль при этом не извлекается из диалога и не удаляется при очистке памяти.

## Запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте `.env` по примеру `.env.example`:

```bash
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-4o
OPENAI_TOKEN_COUNTING=estimate
PORT=3001
```

3. Запустите frontend и backend:

```bash
npm run dev
```

4. Откройте локальный адрес Vite, обычно `http://localhost:5173`.

## Как работает память

Backend хранит слои памяти в SQLite отдельно:

- `user_profiles` — явные настройки персонализации: имя, описание, стиль, формат, ограничения и признак активного профиля.
- `short_term_messages` — сообщения текущего диалога.
- `working_memory` — JSON текущей задачи с фиксированными ключами `goal`, `taskData`, `constraints`, `openQuestions`, `nextSteps`.
- `long_term_memory` — JSON долговременной памяти с ключами `profile`, `preferences`, `decisions`, `knowledge`.

Контекст для ответа собирается явно:

1. system prompt агента;
2. активный user profile;
3. блок long-term memory;
4. блок working memory;
5. последние N сообщений short-term memory;
6. текущий пользовательский ввод.

Если текущее сообщение явно противоречит профилю, оно имеет приоритет для этого ответа. Профиль отвечает за стабильные настройки общения, а long-term memory — за факты, решения и знания, которые агент извлек из прошлых диалогов.

Если извлечение памяти возвращает пустой или невалидный JSON, существующие значения остаются без изменений.

## API

- `GET /api/memory` — возвращает `shortTermMessages`, `workingMemory`, `longTermMemory` и статистику.
- `GET /api/profiles` — возвращает список профилей и активный профиль.
- `POST /api/profiles/:id/activate` — делает профиль активным.
- `PUT /api/profiles/:id` — обновляет имя, описание, стиль, формат и ограничения профиля.
- `GET /api/profile-comparisons` — возвращает сохраненную историю вопросов и сравнительных ответов.
- `DELETE /api/profile-comparisons` — очищает историю сравнений и все слои памяти, не удаляя профили.
- `GET /api/config` — возвращает модель, контекстное окно и defaults памяти.
- `POST /api/context-preview` — считает токены следующего запроса и показывает, сколько short-term сообщений попадет в контекст.
- `POST /api/profile-comparison` — отправляет один вопрос через каждый профиль параллельно, не дублируя сообщения в памяти.
- `POST /api/chat` — отправляет сообщение агенту, сохраняет диалог в short-term и обновляет working/long-term память.
- `DELETE /api/memory` — очищает все три слоя памяти, сохраняя пользовательские профили.

## Проверка

```bash
npm test
npm run build
```

Ручной сценарий:

1. Введите общий вопрос, например: «Как устроена event loop в JavaScript?».
2. Нажмите `Сравнить ответы` и дождитесь ответов в двух профильных колонках.
3. Убедитесь, что учебный ответ подробнее и содержит объяснение логики или пример.
4. Проверьте под ответами размер `Profile block` и расход токенов.
5. Измените стиль или ограничения одного профиля и повторите сравнение.
6. Убедитесь, что изменился только ответ соответствующего профиля.
