# День 8: Работа с токенами

Минимальное web-приложение с отдельной сущностью агента, SQLite-историей и подсчетом токенов. Пользователь пишет запрос в чате, frontend отправляет его на backend, backend сохраняет сообщения, считает токены текущего запроса/истории/полного input и вызывает LLM через OpenAI Responses API.

Интерфейс показывает токены и стоимость каждого шага, суммарную стоимость диалога и текущий размер контекста. Контекст сравнивается только с реальным лимитом выбранной модели. По умолчанию используется `gpt-3.5-turbo` с окном контекста 16 385 токенов.

## Запуск

1. Установите зависимости:

```bash
npm install
```

2. Создайте `.env` по примеру `.env.example` и добавьте ключ:

```bash
OPENAI_API_KEY=your_openai_api_key_here
OPENAI_MODEL=gpt-3.5-turbo
PORT=3001
```

3. Запустите frontend и backend:

```bash
npm run dev
```

4. Откройте локальный адрес Vite, обычно `http://localhost:5173`.

## Архитектура

- `src/` — компактный React-интерфейс чата на Material UI.
- `server/index.js` — Express API endpoints `GET /api/messages`, `POST /api/chat`.
- `server/LlmAgent.js` — отдельная сущность агента, которая инкапсулирует вызов LLM.
- `server/TokenUsageAnalyzer.js` — подсчет input tokens, лимиты контекста и стоимость.
- `server/MessageStore.js` — SQLite-хранилище сообщений.

API-ключ используется только на backend и не отправляется в браузер.

История хранится в локальном файле `server/data/messages.sqlite`. Этот файл создается автоматически при запуске backend и не коммитится в git.

## Что считается

Перед вызовом модели backend считает:

- `currentRequestTokens` — токены текущего пользовательского сообщения;
- `historyTokens` — токены system message и всей сохраненной истории;
- `fullInputTokens` — полный input, который уйдет в модель;
- `context` — реальный лимит модели, оставшиеся токены и статус `ok`, `near_limit` или `overflow`.

После ответа модели backend сохраняет:

- `inputTokens`, `cachedInputTokens`, `outputTokens`, `reasoningTokens`, `totalTokens`;
- примерную стоимость текущего шага;
- cumulative tokens/cost по всему диалогу.

Для точного input-подсчета используется официальный endpoint `/v1/responses/input_tokens`. Если endpoint недоступен, приложение возвращается к локальной оценке и помечает метод как `fallback`.

Если полный input больше реального окна контекста модели, backend возвращает 400 и не вызывает модель. Сообщение, которое не прошло из-за лимита, не сохраняется в SQLite.

## Проверка

1. Короткий диалог:

```text
Привет! Ответь одним предложением.
```

Под сообщением и ответом появятся токены текущего шага и цена ответа.

2. Длинный диалог:

```text
Запомни подробное описание проекта: ...
```

Повторите несколько длинных сообщений. Нижняя строка покажет рост контекста и суммарной стоимости, потому что агент каждый раз отправляет модели всю историю.

3. Переполнение:

Поставьте небольшой `Лимит чата` в UI и продолжайте диалог длинными сообщениями. Когда `fullInputTokens` превысит effective limit, backend вернет ошибку 400 и не будет вызывать модель. Это та же механика, которую можно использовать для тарифных лимитов: модель может уметь больше, но продукт разрешает меньше.
