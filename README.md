# День 19 · Композиция MCP-инструментов

Автоматический пайплайн из трёх MCP-инструментов над каталогом услуг Altegio:
`pipeline_search` получает данные → `pipeline_summarize` обрабатывает → `pipeline_save_to_file`
сохраняет отчёт в файл. Цепочка выполняется автоматически на любой вопрос об услугах в чате
или по запросу `POST /api/pipeline/run`; отчёт сохраняется каждый раз. Ветка предыдущего дня: `day_18`.
В проекте оставлено только то, что нужно дню 19: вход в Altegio, три инструмента пайплайна и чат.

## Пайплайн

```
pipeline_search { query?, limit }          → search  { query, searchMode, truncated, fetchedAt, items[], checksum }
pipeline_summarize { source: search }       → report  { sourceChecksum, count, priced, unpriced, byCurrency[], items[], text, checksum }
pipeline_save_to_file { report, format, name? } → file { file, format, bytes, reportChecksum, savedAt }
```

- **search** — поиск услуг филиала через Altegio V2 (`AltegioApi` из `server/mcp/altegio.js`),
  лимит 1–100 (по умолчанию 50).
- **summarize** — детерминированный код, без модели: количество услуг, с ценой и без,
  диапазон и средняя минимальная цена, три самых доступных и дорогих — отдельно по каждой валюте.
  `null` не считается нулём, валюты не смешиваются.
- **saveToFile** — Markdown (сводка + таблица услуг + checksum) или JSON (отчёт целиком).
  Каталог `data/reports/` (или `REPORTS_DIR`). Имя очищается до букв, цифр и `-`, поэтому
  выйти за каталог нельзя; по умолчанию `services-<время>`. Существующий файл не перезаписывается,
  запись атомарная через временный файл, права `0600`.

**Корректность передачи данных.** Каждый шаг подписывает свой выход SHA-256 от канонического JSON
(ключи отсортированы). Следующий шаг пересчитывает хеш входа и отклоняет данные, если что-то изменено,
потеряно или добавлено («Данные повреждены при передаче»). Выход сводки содержит `sourceChecksum`,
выход сохранения — `reportChecksum`; функция `runPipeline`
(`server/pipeline/runner.js`) сверяет их с предыдущим шагом. При ошибке шага следующие помечаются `skipped`, файл не создаётся.

**Автоматический запуск из чата.** Модели доступен один инструмент — `services_report`
(`query`, `limit`, `format`). Её решение — только что искать. Вызов запускает `runPipeline`: backend
сам вызывает три MCP-инструмента по очереди и передаёт полный выход шага во вход следующего,
без участия модели. Поэтому на любой вопрос об услугах цепочка выполняется целиком и файл сохраняется,
а данные не искажаются при пересказе. Модель получает `status`, сводку `report` и имя файла `file`.

## Запуск

Нужен Node.js 20.19+.

```sh
npm install
cp .env.example .env # только если .env ещё нет
npm run dev
```

Frontend: http://localhost:5173. Backend: http://127.0.0.1:3001.
Собранное приложение: `npm run build`, затем `npm start`.

Настройки `.env`: `OPENAI_API_KEY`, `OPENAI_MODEL`, `ALTEGIO_PARTNER_TOKEN`, `PORT`, необязательный `REPORTS_DIR`.
Для автоматического восстановления подключения после перезапуска задайте также
`ALTEGIO_USER_TOKEN` и `ALTEGIO_LOCATION_ID`. Backend проверяет филиал по доступному
пользователю списку. Единственный доступный филиал выбирается автоматически.
Если список не загрузился, выберите филиал в форме.

Вход через форму хранится только в памяти; после перезапуска потребуется войти снова.
Пароль не сохраняется, токен не возвращается браузеру или модели. Выход удаляет токен
из текущего процесса, но не редактирует `.env`.
Это локальное приложение с одним подключением и общим диалогом, без многопользовательских сессий.

## Как пользоваться

1. Войдите в Altegio через форму слева и выберите филиал.
2. Задайте агенту любой вопрос об услугах, например:
   - «Какие есть стрижки и сколько они стоят?»;
   - «Сделай отчёт по всему каталогу в json».
   Отдельно просить сохранить файл не нужно.
3. Под ответом агента видны три MCP-вызова по порядку — `pipeline_search`, `pipeline_summarize`,
   `pipeline_save_to_file` — с параметрами и результатами. По ним можно сверить, что выход шага
   передан во вход следующего и checksum совпадают.
4. Под ответом появляется ссылка «Открыть отчёт …» — файл открывается в новой вкладке браузера.
   Сам файл лежит в `data/reports/` (каталог исключён из Git).

## MCP и HTTP API

| MCP-инструмент | Аргументы |
|---|---|
| `pipeline_search` | `query`, `limit` (1–100, по умолчанию 50) |
| `pipeline_summarize` | `source` — полный результат `pipeline_search` |
| `pipeline_save_to_file` | `report` — полный результат `pipeline_summarize`, `format` (`md`/`json`), `name` |

`POST /api/pipeline/run` `{ query?, limit?, format?, name? }` выполняет всю цепочку кодом, без модели,
и возвращает `{ status, steps: [{ name, status, durationMs, input, output }], report, file }`.
`GET /api/reports/:file` отдаёт сохранённый отчёт только для чтения (имя проверяется,
выход за каталог отчётов невозможен). Сохранены маршруты `/api/altegio/*`, `GET /api/health`, `GET/DELETE /api/messages`, `POST /api/chat`.
MCP-клиент проверяет имена и аргументы по общему реестру (`server/mcp/tools.js`).
Агент запускает пайплайн не больше пяти раз за запрос.

## Проверка

```sh
npm test
npm run build
npm run mcp:list
```

Тесты не требуют ключей: реальные MCP-процессы по stdio и HTTP приложения работают с подменёнными
ответами Altegio и модели и временными каталогами. Проверяются статистика и checksum, отказ при
подмене данных, имена файлов и запрет перезаписи, полная цепочка через MCP, остановка при ошибке
шага, автоматическая цепочка из одного вызова агента, ссылка на файл и HTTP-запуск.

Документация: [услуги Altegio V2](https://developer.alteg.io/en/b2b-v2/openapi/services/list_services),
[ключи Altegio](https://developer.alteg.io/en/get-api-key).
