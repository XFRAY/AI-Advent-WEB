# День 17 · MCP Altegio

Чат с агентом, который самостоятельно вызывает собственный MCP-инструмент
`altegio_list_services` и использует полученные услуги и цены в ответе.

## Запуск

Нужен Node.js 20.19+.

```sh
npm install
cp .env.example .env # только если .env ещё нет
# Заполните .env своими ключами
npm run dev
```

Откройте http://localhost:5173. Backend: http://127.0.0.1:3001.
Для запуска собранного приложения: `npm run build`, затем `npm start`.

Настройки `.env`: `OPENAI_API_KEY`, `OPENAI_MODEL` (сохранена модель проекта),
`ALTEGIO_PARTNER_TOKEN`, `PORT` (3001).
Файл `.env` исключён из Git. Не добавляйте секреты в frontend или сообщения.

## Авторизация Altegio

Над чатом находится форма «Подключение Altegio». Введите логин и пароль вашего
бизнес-аккаунта и нажмите «Войти». Backend вызывает `POST /api/v1/auth`, получает
`data.user_token` и перезапускает MCP-подключение с новым токеном. Ключ партнёра задаётся в `.env`. После входа загружаются доступные пользователю
филиалы через `GET /api/v1/companies?my=1` с пагинацией. Единственный филиал
выбирается автоматически; если их несколько, выберите нужный в выпадающем списке.
При отсутствии филиалов показывается сообщение. Ошибку загрузки можно повторить
кнопкой «Обновить список филиалов». При смене филиала MCP перезапускается, история
очищается. Выбор хранится до выхода или перезапуска сервера.
Пароль не сохраняется и не передаётся модели. User Token хранится только в памяти
backend и MCP-процесса, не возвращается в браузер. После обновления страницы вход
сохраняется; после перезапуска сервера нужно войти заново. Кнопка «Выйти» удаляет
локальный токен и закрывает MCP-процесс. Вход и выход очищают историю чата.
Это одна общая авторизация локального приложения, а не многопользовательские сессии.

Для CLI можно задать `ALTEGIO_USER_TOKEN` и `ALTEGIO_LOCATION_ID` в окружении; при этом он
подхватывается при старте. Выход очищает его только в текущем процессе, поэтому для
входа исключительно через UI уберите эту переменную из `.env`.

## Как это работает

1. Backend запускает `server/mcp/server.js` отдельным процессом через stdio.
2. MCP SDK регистрирует инструмент с Zod-схемой; клиент получает `listTools()`.
3. Агент передаёт описание и JSON Schema модели через Responses API.
4. Модель возвращает `function_call`; backend проверяет имя и аргументы,
   выполняет MCP `callTool()` и отправляет модели `function_call_output` с исходным `call_id`.
5. Модель отвечает по результату. В чате раскрываются параметры, статус и JSON результата.

Инструмент принимает `query` (необязательный поиск по названию без учёта регистра)
и `limit` (1–100, по умолчанию 20). Филиал выбирается в интерфейсе; backend проверяет его наличие в списке доступных.

Используется `GET https://api.alteg.io/api/v2/locations/{location_id}/services`
с `Accept: application/vnd.api.v2+json`, авторизацией Partner + User и `include=company_links`.
Страницы обходятся через `page`/`limit` до конца каталога либо до первого совпадения
сверх запрошенного лимита. В последнем случае `truncated: true`.
Если буквальный поиск ничего не нашёл, возвращаются кандидаты из каталога
с `searchMode: catalog_fallback` и подсказкой для модели. Агент отбирает услуги
по смыслу, в том числе при разных языках запроса и названий. Кандидаты ограничены
`limit`; при `truncated: true` агент уточняет поиск на языке каталога.

Ответ: `services: [{id, title, price_min, price_max, currency}]`, `query`, `limit`, `truncated`.

V2 гарантирует ID и название; цены могут отсутствовать. Цены читаются из атрибутов
услуги или явно связанного текущего филиала, отсутствующие значения возвращаются как `null`.
Нулевая цена сохраняется. Валюта не подставляется. Никакие записи или данные Altegio не меняются.

На запрос допускается до пяти вызовов инструмента. Таймаут каталога — 20 секунд,
MCP-вызова — 30 секунд; максимум 100 страниц. Ошибки API не раскрывают ключи и сырые HTTP-ответы.
История хранится в памяти до перезапуска. Одновременно выполняется один запрос;
очистка во время ответа блокируется. Это локальное учебное приложение с одним общим диалогом.

## API

- `GET /api/altegio/auth` — статус подключения без секретов.
- `POST /api/altegio/auth` с `{login, password}` — войти в Altegio.
- `DELETE /api/altegio/auth` — выйти и очистить историю.
- `POST /api/altegio/locations/refresh` — обновить доступные филиалы.
- `POST /api/altegio/location` с `{locationId}` — выбрать филиал из списка.
- `GET /api/health` — состояние HTTP-сервера.
- `GET /api/messages` — `{messages}`.
- `DELETE /api/messages` — очистить историю.
- `POST /api/chat` с `{message}` — `{answer, toolCalls, messages}`.

## Проверка

```sh
npm run mcp:list
npm test
npm run build
```

Тесты не требуют ключей: настоящий MCP-процесс обменивается сообщениями через stdio,
а HTTP Altegio и модель подменяются. Проверяется также вся цепочка через `/api/chat`.

Ручная проверка с настоящими ключами:

1. Войти через форму Altegio и спросить «Какие услуги доступны и сколько стоят?».
2. Раскрыть MCP-вызов: `altegio_list_services`, параметры, успешный результат.
3. Сверить названия и цены в ответе с JSON инструмента.
4. Спросить конкретную услугу и проверить фильтрацию.
5. Очистить чат и проверить обычное приветствие без MCP-вызова.
